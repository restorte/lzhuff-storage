# lzhuff-store

Сервис хранения файлов на Go с прозрачным сжатием: загруженные файлы жмутся
**собственным кодеком LZ77 + Huffman** (без `compress/flate`), на диске хранится
только сжатый контейнер, а при скачивании оригинал восстанавливается на лету.
Обработка асинхронная — очередь задач живёт в PostgreSQL.

Учебный проект: каждый слой — сжатие, хранилище, очередь, HTTP — написан и покрыт
тестами с нуля.

---

## Возможности

- **Собственный движок сжатия** — LZ77 (поиск по хеш‑цепочкам, ленивое
  сопоставление) + энтропийное кодирование Хаффмана. На тексте ~30×.
- **Не раздувает несжимаемое** — если сжатие не помогло (JPEG, ZIP, PDF), данные
  кладутся как есть: выход никогда не больше входа + 1 байт.
- **PostgreSQL как очередь** — задачи захватываются атомарно через
  `UPDATE … FOR UPDATE SKIP LOCKED`, поэтому N воркеров не берут одну задачу
  дважды **без единого мьютекса**.
- **Проверка целостности** — перед удалением оригинала контейнер читается с диска,
  распаковывается и сверяется с SHA‑256, снятой при загрузке. Не сошлось —
  задача помечается ошибкой, а оригинал остаётся.
- **Восстановление после сбоя** — задачи, зависшие в `processing`, возвращаются
  в очередь на старте.
- **Корректная остановка** — `Ctrl+C` даёт серверу и воркерам завершиться чисто.
- **Устойчивость к битым данным** — обрезанный или испорченный контейнер даёт
  ошибку, а не панику (проверяется фаззингом).

## Архитектура

```
        HTTP (net/http)                POST /files → 202 {id}
              │                        GET  /files/{id} → 200 / 202 / 400 / 404
              ▼
        PostgreSQL (pgx)               таблица files: машина состояний
              │                        pending → processing → done | error
              ▼
        пул воркеров                   4 горутины, захват через БД‑арбитр,
              │                        сверка SHA‑256, graceful shutdown
              ▼
        codec  =  LZ77  +  Huffman     хеш‑цепочки, ленивое сопоставление
              │                        дерево в заголовке, stored‑block fallback
              ▼
        storage (диск)                 атомарная запись: temp‑файл + rename
```

| Пакет | Ответственность |
|-------|-----------------|
| `internal/lz77` | Словарное сжатие: хеш‑цепочки, ленивое сопоставление, декод с перекрытием |
| `internal/huffman` | Энтропийное кодирование: дерево частот, битовый I/O (MSB‑first) |
| `internal/codec` | Двухступенчатые `Compress`/`Decompress` + stored‑block fallback |
| `internal/db` | Репозиторий `files`: создание, атомарный захват, смена статусов |
| `internal/storage` | Блобы на диске по ключу, атомарная запись |
| `internal/worker` | Пул воркеров: захват → сжатие → проверка → пометка → уборка |
| `internal/api` | HTTP‑хендлеры |
| `cmd/server` | Сборка и жизненный цикл |

## Установка

**1. База и миграция:**

```bash
psql -U postgres -c "CREATE DATABASE lzhuff;"
psql -U postgres -d lzhuff -f migrations/0001_init.sql
```

> На Windows `psql` обычно не в `PATH` — вызывайте по полному пути:
> `"/c/Program Files/PostgreSQL/18/bin/psql.exe" -U postgres …`

**2. Файл `.env`** (он в `.gitignore`):

```
DATABASE_URL=postgres://postgres:пароль@localhost:5432/lzhuff
```

## Конфигурация

| Переменная | Обязательна | По умолчанию | Описание |
|------------|-------------|--------------|----------|
| `DATABASE_URL` | да | — | Строка подключения к PostgreSQL |
| `STORAGE_ROOT` | нет | `storage` | Каталог для `originals/` и `containers/`; относительный путь считается от рабочего каталога сервера |
| `ADDR` | нет | `:8080` | Адрес прослушивания HTTP |

Максимальный размер загрузки — 32 МБ (`defaultMaxUpload` в `internal/api`).
Число воркеров — 4 (`cmd/server/main.go`).

## API

### `POST /files` — загрузка

Тело — **сырые байты файла** (не multipart). Необязательный параметр `?name=`.

```bash
curl -X POST "http://localhost:8080/files?name=notes.txt" --data-binary @notes.txt
```

```json
{ "id": "f286f5d1-9ed3-41a1-a35b-8620921bf323" }
```

| Статус | Значение |
|--------|----------|
| `202 Accepted` | Принято в очередь, сжатие идёт в фоне |
| `413 Payload Too Large` | Файл больше лимита |
| `500` | Ошибка сервера |

### `GET /files/{id}` — скачивание и статус

```bash
curl -OJ "http://localhost:8080/files/f286f5d1-9ed3-41a1-a35b-8620921bf323"
```

Флаги `-OJ` сохраняют файл под исходным именем — сервер отдаёт его в заголовке
`Content-Disposition`.

| Статус | Значение |
|--------|----------|
| `200 OK` | Готово — тело содержит распакованный оригинал |
| `202 Accepted` | Ещё в обработке — `{ "status": "pending" }` |
| `400 Bad Request` | id не UUID |
| `404 Not Found` | Нет такого id |
| `500` | Обработка провалилась или сбой сервера |

## Тестирование

```bash
go test ./...
```

Пакеты чистой логики (`lz77`, `huffman`, `codec`, `storage`) не требуют ничего
внешнего. Интеграционные (`db`, `worker`, `api`) работают с живой базой и
**пропускаются**, если `DATABASE_URL` не задан:

```bash
export $(grep -v '^#' .env | xargs)
go test ./...
```

Тесты, которым нужна база, сериализуются между собой через advisory lock
PostgreSQL, поэтому `go test ./...` можно запускать как обычно — без `-p 1`.

**Фаззинг декодера** (контейнеры читаются с диска и не считаются доверенными):

```bash
go test -run=XXX -fuzz=FuzzDecompress -fuzztime=30s ./internal/codec
```

## Как устроено сжатие

1. **LZ77** заменяет повторы на токены `(отступ, длина)`. Кандидаты ищутся по
   хеш‑цепочке над 3‑байтными префиксами, ленивое сопоставление заглядывает на
   байт вперёд ради лучшего разбора. Окно 4096, длина 3–18, токен 2 байта
   (12 бит отступ + 4 бита длина), управляющий байт на каждые 8 элементов.
2. **Huffman** кодирует получившийся поток: частым байтам — короткие коды.
   Дерево сериализуется в заголовок, чтобы декодер его восстановил.
3. **Stored‑block** — результат сравнивается с исходником, и если сжатие не
   помогло, данные пишутся сырыми с флагом в первом байте.

Huffman работает лучше *после* LZ77, чем на сырых данных: в потоке токенов и
литералов частоты байт сильно перекошены — ступени усиливают друг друга.

Замеры на 10 000 байт:

| Вход | Результат |
|------|-----------|
| Повторяющийся текст | **334 байта** (~30×) |
| Случайные байты | **10 001 байт** (+1 байт флага) |
